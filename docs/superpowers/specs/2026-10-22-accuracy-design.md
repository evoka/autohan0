# 판단 정확도 개선 설계 (2026-10-22)

## 왜

autohan0은 기존 평가(Tatoeba 깨끗한 문장, 개발자 대화)에서 거의 틀리지 않지만, 참고 프로젝트
Tacit·araso의 어려운 문장 모음(숫자·단위, 한 글자 영어+한글, 약어+조사, 따옴표, 코드 토큰)으로
돌려 보면 뚜렷한 구멍이 있다(세벌식 390·최종 모두). 이 설계는 **그 구멍을 메우고, 두 프로젝트에서
효과가 수치로 확인된 기법만** 들여온다. 사용자(세벌식 390)가 실제로 치는 글의 정확도가 목표다.

측정한 현재 상태(세벌식 최종, 엔진 `main` 275fc50):

- 숫자 + 한글 단위·조사: `3개`→`3kr`, `10분`, `2025년에`, `v0.8.5로`, `500을`, `F1이`. 가장 많다.
  원인: "영어 머리 + 한글 꼬리" 분리는 머리에 글자가 2개 이상이어야 후보가 된다.
- 한 글자 영어 + 한글: `n제`, `x축`, `B급`, `A팀` — 같은 규칙으로 43/75 실패.
- A 모드에서 대문자를 Shift 숫자·기호로 읽음: `UI같은건`→`67같은건`, `N제`→`-제`, `K는`→`2는`.
- 따옴표·괄호 뒤 한글: `"contents"라고`→`"conte선·라고` (분리 지점이 영숫자 뒤로만 제한).
- 코드 토큰 + 조사: `k8s에`→`긘에` (드문 음절이라도 한글 전체 읽기가 코드 토큰 영어를 이김).
- 세벌식 최종에서 A 모드로 친 `~`가 `※`로 바뀜(`뭐라고~`).
- 단독으로 친 짧은 영어 단어(`hr`, `kg`, `lbs`)가 한글로: 52,582개 중 77개. 본질적 중의성이라
  문맥·학습·앱별 정책으로만 줄일 수 있다.

## 목표 / 비목표

목표

1. 위 실패 유형을 고치되, **바꾸면 안 되는 것을 바꾸는 쪽이 더 나쁘다**는 원칙을 지킨다
   (Tacit: "자르지 않아야 할 세트"에 4배 가중치).
2. 고치기 전에 평가 틀을 먼저 둔다. 어려운 문장은 우리가 직접 쓴다(Tacit 데이터는 AGPL이라 복사하지
   않는다). `npm test`가 회귀를 잡는다.
3. 참고 프로젝트에서 효과가 확인된 것만: 숫자 앞뒤 문맥(Tacit writing.numbers 62→100), 약어
   고정 점수, 2회 교정 학습(+1회 약한 기울기), 앱별 엄격 모드(터미널), URL·경로 보호.

비목표

- 두벌식 자판(조합기부터 별도 프로젝트), 일본어, 자동완성, 대시보드.
- 한글 머리 + 영어 꼬리(`코드review`, `챗GPT`): catchtype도 안 하는 경계. 다음 단계 후보.
- 학습형 선택기(CRF, softmax): Tacit에서 7종 모두 실사용 회귀로 기각.
- 30일 만료 학습: 엔진에 시각이 없어 지금은 뺀다.

## 결정

D1. **평가 틀**: `packages/engine/eval/harness.ts`(문장→키열, 두 모드로 치기)와
`packages/engine/test/guard.test.ts`(npm test에 포함). guard는 (a) 직접 쓴 어려운 문장
`test/fixtures/hard.ts`(유형별, `pass`로 표시한 항목은 두 모드 모두 맞아야 함), (b) en.json 전체
단어를 A 모드로 쳤을 때 바뀌는 수 ≤ 상한(기준 77, 과제마다 낮춤), (c) ko.json 어절을 가 모드로
쳤을 때 바뀌는 수 ≤ 1, (d) 코드 식별자 목록(`IDENTIFIERS`)은 A 모드에서 0개 바뀜.

D2. **분리 머리 조건 완화**: 머리가 글자 2개 이상 **또는 숫자를 포함**하면 후보. 분리 지점은
영숫자 뒤 **또는 닫는 따옴표·괄호(`"')]}`) 뒤**.

D3. **약어 모형**: 2–6자 모두 대문자 run의 영어 점수는 `max(기존, log 0.001 + (길이−2)·log 0.25)`.
소문자 단어 빈도로 약어(UI, PR, CI)를 재지 않는다. A 모드 전체 대문자 토큰 → 한글 NEG 규칙은 유지.

D4. **A 모드 Shift 회의**: A 모드로 친 단어에서, 한글 읽기가 **대문자 글자 키를 기호·숫자로** 읽는
키마다 `log 0.1`을 뺀다(한글 후보와 분리 꼬리 모두). 가 모드 단어는 그대로(`KHK:`=2024).

D5. **한 글자 머리**: 머리가 글자 하나뿐이면, 꼬리(완성 시)가 조사·단위 목록이나 한국어 어절 사전에
있을 때만 후보. 치는 중에는 접두 질량 > 0이면 된다.

D6. **코드 토큰 영어 읽기**: 숫자에 붙은 3자 이하 글자 run은 `max(단어 확률, 글자당 log 0.15)`
(`k8s`, `h264`, `3e-4`, `F1`).

D7. **A 모드 기호 유지**: A 모드로 친 단어를 한글로 바꿀 때, 자판표 값이 **자모가 아닌 기호**인 키는
QWERTY 글자를 그대로 둔다(최종: `~`→`※` 안 함). 가 모드 단어는 자판표 기호 그대로.

D8. **URL·경로 보호**: 토큰에 `://`가 있거나 `www.` `~/` `./` `../` `localhost:`로 시작하거나
`/x/`꼴 경로이거나 `글자@글자`이면 영어 후보만 둔다(두 모드 모두). `.`·`/` 하나만으로는 아님.

D9. **학습 2단계**: 같은 말을 **2번** 되돌리면 배움(지금 3번). **1번** 되돌리면 그 키열의 친 그대로
읽기에 +3(약한 기울기). 1회 항목도 배운 말 목록에 `count: 1`로 저장·복원된다(macOS Store·웹 형식
불변). 목록에서 지우면 둘 다 사라진다.

D10. **앱별 엄격 모드**(macOS): `Settings.strictApps`(기본: Terminal, iTerm2, Ghostty, Warp,
Alacritty, kitty, WezTerm). 엄격 앱에서 A 모드로 친 단어는 한글(또는 분리)로 바꾸려면 영어보다
사전 확률 포함 **4 이상** 앞서야 하고, **3키 이하**는 바꾸지 않는다. 가 모드로 친 단어(한글→영어)는
평소대로. 메뉴에 "<앱>에서 엄격하게" 토글. 엔진 API `setStrict(on)`.

D11. 값(`log 0.1`, `+3`, `4`, `3키`)은 출발점이다. guard와 eval이 판정하며, 바꾸면 안 되는
목록이 늘어나는 변경은 넣지 않는다.
