# autohan0 — 세벌식 한/영 자동 전환

한/영 키를 누르지 않고 쳐도, **세벌식으로 친 한글은 한글로, 한글 상태에서 친 영어는 영어로** 키마다 고쳐 주는 엔진과 브라우저 데모, macOS 메뉴바 앱입니다.
[catchtype.com](https://catchtype.com/#try)의 동작(두벌식 전용)을 **세벌식 최종(기본)과 세벌식 390** 기준으로 다시 만들었습니다.

- `packages/engine` — TypeScript 엔진. DOM·Node 의존이 없어서 macOS 메뉴바 앱 같은 다른 래퍼에서도 그대로 쓸 수 있습니다.
- `apps/web` — catchtype의 "직접 쳐 보세요" 구역 같은 한 페이지 데모. 엔진이 브라우저 안에서 돌고, 친 키는 어디에도 보내지 않습니다.
- `apps/macos` — catchtype의 macOS 앱처럼 모든 앱에서 동작하는 메뉴바 앱(Swift). 같은 엔진을 JavaScriptCore에서 돌립니다. [아래 절](#macos-메뉴바-앱-appsmacos) 참고.

## 실행

Node 20 이상(개발은 Node 25, npm 11)에서 확인했습니다.

```bash
npm install
```

데모(Vite 개발 서버, http://localhost:5178):

```bash
npm run dev
```

테스트(SPEC 7절 수용 테스트 28개 + 엔진 동작 테스트):

```bash
npm test
```

정확도 평가(Tatoeba 문장을 먼저 내려받음, 평가에만 씀):

```bash
sh scripts/fetch_eval_data.sh
```

```bash
cd packages/engine && npx vitest run --config vitest.eval.config.ts
```

배포용 빌드(`apps/web/dist`):

```bash
npm run build
```

데모에서는 **OS 입력 소스를 영어(ABC)로 두고** 치세요. 데모는 `keydown`의 `event.code`(물리 키)와 Shift로 QWERTY 문자를 구해 엔진에 넘기고, 브라우저 기본 입력은 막습니다(`preventDefault`). 한/영 키는 키보드의 한/영 키(`Lang1`/`HangulMode`), **Shift+Space**, 화면의 [한/영 전환] 단추 중 아무거나 쓰면 됩니다.

## macOS 메뉴바 앱 (`apps/macos`)

catchtype의 macOS 앱이 하는 일을 세벌식 엔진으로 합니다. 메뉴바에 **가**/**A**가 뜨고, 어느 앱에서 치든 키마다 고쳐 넣습니다. macOS 13 이상, Apple Silicon(arm64)에서 확인했습니다.

### 빌드

Xcode(또는 Command Line Tools, Swift 5.9 이상)와 Node가 필요합니다. 저장소 루트에서 `npm install`을 한 번 한 뒤:

```bash
apps/macos/build.sh
```

`apps/macos/build/autohan0.app`이 생깁니다. 스크립트는 ① 엔진과 단어 데이터를 JS 파일 하나로 묶고(`npm run build:jsc` → `apps/macos/Resources/autohan0-engine.js`, 약 1.1MB) ② `swift build -c release` ③ 앱 번들을 만들어 ④ 서명합니다(`AUTOHAN0_SIGN_IDENTITY` → 키체인의 Developer ID Application → `apps/macos/.sign-identity`에 적은 인증서 이름 → `autohan0 local signing` → 없으면 ad hoc 순). 공증·배포는 하지 않습니다.

### 실행과 권한

```bash
open apps/macos/build/autohan0.app
```

- 처음 띄우면 **손쉬운 사용** 권한을 묻습니다. 시스템 설정 › 개인정보 보호 및 보안 › 손쉬운 사용에서 autohan0을 켜면 몇 초 안에 메뉴바가 흐린 `가A`에서 `가` 또는 `A`로 바뀝니다(다시 띄울 필요 없음). 메뉴 맨 위 줄이 `자동 변환 중 · …`이면 동작 중입니다.
- **다시 빌드하면 권한이 풀립니다.** ad hoc 서명은 빌드마다 서명이 달라져 macOS가 다른 앱으로 봅니다. 목록에서 스위치를 껐다 켜는 것으로는 안 되고, autohan0을 선택해 **"−"로 지운 뒤**(암호·Touch ID 확인) 메뉴의 **"손쉬운 사용 권한 켜기…"**를 눌러 다시 넣고 켜야 합니다. **자주 빌드한다면 자체 서명 인증서를 한 번 만들어 두세요.** 그러면 빌드 사이에 권한이 유지됩니다.
  **Apple Developer 계정이 있으면** Developer ID Application 인증서를 키체인에 넣어 두세요. `build.sh`가 그 인증서를 먼저 찾아 hardened runtime과 타임스탬프를 붙여 서명하고, 권한은 빌드 사이에 유지됩니다(공증은 배포할 때만 `xcrun notarytool`로 따로). Xcode › Settings › Accounts › 팀 선택 › Manage Certificates… › "+" › **Developer ID Application**을 누르면 인증서가 만들어져 로그인 키체인에 들어갑니다. `security find-identity -v -p codesigning`에 보이면 됩니다.

  **Xcode에 Apple Development 인증서가 있으면** 그 이름을 `apps/macos/.sign-identity` 한 줄로 적어 두세요(저장소에는 올라가지 않음). 예: `Apple Development: 홍길동 (ABCDE12345)`. 같은 이름의 인증서가 여럿이면(다시 만든 인증서) `build.sh`가 Apple에서 **폐기된 것은 건너뜁니다**: `security find-identity`는 폐기된 인증서도 유효로 보여 주지만, 그것으로 서명한 앱을 열면 macOS가 "악성 코드가 차단되고 휴지통으로 이동함"을 띄우고 지웁니다. 남은 것이 모두 폐기됐으면 빌드를 멈춥니다. 키체인 접근에서 폐기된 인증서를 지워 두면 깔끔합니다.

  계정이 없으면 자체 서명 인증서를 씁니다. 가장 쉬운 방법은 스크립트 한 번 실행입니다(로그인 키체인에 자체 서명 인증서를 만들고 코드 서명용으로 신뢰 설정, 암호 확인 창이 뜰 수 있음):

  ```bash
  apps/macos/make-signing-cert.sh
  ```

  키체인 접근 앱에서 직접 만들어도 됩니다.

  1. 키체인 접근 앱 › 메뉴 **키체인 접근 › 인증서 지원 › 인증서 생성…**
  2. 이름 `autohan0 local signing`, 신원 유형 **자체 서명 루트**, 인증서 유형 **코드 서명** → 생성 (로그인 키체인에 들어감)
  3. `apps/macos/build.sh`가 이 이름의 인증서를 찾아 자동으로 씁니다(다른 인증서는 `AUTOHAN0_SIGN_IDENTITY="이름"`). 처음 서명할 때 "codesign이 키체인의 키에 접근하려고 합니다"가 뜨면 **항상 허용**. 서명이 "신뢰하지 않음"으로 실패하면 키체인 접근에서 인증서를 열어 신뢰 › 코드 서명을 **항상 신뢰**로 바꾸세요.
  4. 인증서로 바꾼 첫 빌드에서만 위처럼 권한을 한 번 더 지우고 다시 넣으면, 그다음 빌드부터는 그대로 유지됩니다.
- **다른 한/영 전환 앱과 같이 켜지 마세요.** gksdud처럼 키를 가로채는 앱이 함께 돌면 키 입력이 겹칩니다. 메뉴에도 경고가 뜹니다.

### 배포판(DMG) 만들기

Developer ID 인증서가 키체인에 있고 공증 자격 증명을 한 번 저장해 두면, 스크립트 하나로 서명·공증된 DMG가 나옵니다.

```bash
xcrun notarytool store-credentials "autohan0-notary" --apple-id <Apple ID> --team-id <팀 ID>
```

앱 암호(appleid.apple.com › 로그인 및 보안 › 앱 암호)를 물으면 입력합니다. 그다음:

```bash
apps/macos/release.sh
```

빌드 → Developer ID 서명(hardened runtime) → 앱 공증·스테이플 → DMG(앱 + Applications 바로가기) → DMG 서명·공증·스테이플 → `apps/macos/dist/autohan0-<버전>.dmg`와 SHA-256 파일. 공증 없이 DMG만 보려면 `--no-notarize`. 버전은 `Resources/Info.plist`의 `CFBundleShortVersionString`입니다.

### 동작

- **키 가로채기**: `CGEventTap`(세션 단계)으로 keyDown을 받아 물리 키 + Shift를 QWERTY 문자로 바꿔 엔진(`HostAdapter`, `packages/engine/src/host.ts`)에 넘깁니다. 엔진이 고친 결과(`edit`)가 원래 키가 낼 글자와 같으면 원래 키를 그대로 보내고, 다르면 원래 키를 삼키고 백스페이스 n번 + 유니코드 문자열 입력 이벤트를 만들어 보냅니다(`CGEventTapPostEvent`라서 뒤에 친 키보다 먼저 도착). 엔터는 고친 뒤 원래 엔터를 다시 보내고 새로 시작합니다.
- **입력 소스는 ABC로 둡니다.** 켜질 때 한글 입력기를 쓰고 있었으면 가 상태로 시작하고, 끄거나 "○○에서 끄기"한 앱으로 가거나 종료할 때 가 상태였으면 쓰던 한글 입력기로 돌려놓습니다.
- **한/영 키 = 평소 입력 소스를 바꾸는 키.** 시스템 설정의 입력 소스 단축키(이전/다음 입력 소스, 기본 ⌃Space — gksdud를 쓰던 Mac이면 Caps Lock이 F19로 바뀌어 있음)는 가로채서 한/영 키로 쓰고, Caps Lock·🌐처럼 macOS가 직접 입력 소스를 바꾸는 키는 "ABC에서 다른 입력 소스로 바뀜"을 감지해 한/영 키로 칩니다(곧바로 ABC로 되돌림). 메뉴에서 Shift+Space도 켤 수 있습니다. 빠른 두 번 누르기(400ms) 판정은 엔진이 합니다. 되돌리기 편집은 입력 소스가 ABC로 돌아온 뒤 보냅니다 — 한글 입력기가 잠깐 켜진 사이에 보내면 입력기가 그 글자를 다시 한글로 조합해 버리기 때문입니다.
- **커서가 움직일 수 있는 일은 commit**: 마우스 클릭, 방향키·Home/End·🌐 조합, ⌘·⌃·⌥ 조합, Tab·Esc, 포커스 이동, 앱 전환. 그 앞 글자는 더 고치지 않습니다.
- **비밀번호 칸**: 보안 입력(`IsSecureEventInputEnabled()`)이 켜졌거나 포커스된 요소가 보안 텍스트 필드(`AXSecureTextField`)이면 엔진을 우회(`setBypass(true)`)하고 친 그대로 둡니다. 메뉴바는 자물쇠.
- **메뉴**: 자동 한/영 변환 켜기/끄기(⌃⌥W, 어느 앱에서나), 자판(세벌식 최종/390), 한/영 키(감지한 키 표시, Shift+Space), "<앱 이름>에서 끄기", "<앱 이름>에서 엄격하게 (터미널처럼)", 배운 말(눌러서 지우기, 모두 지우기), 키당 처리 시간, 손쉬운 사용 권한 설정, 로그인할 때 열기(`SMAppService`), 종료.
- **엄격하게**: 터미널(Terminal, iTerm2, Ghostty, Warp, Alacritty, kitty, WezTerm이 기본)에서는 영어 상태로 친 글을 한글로 바꾸려면 평소보다 4만큼 더 확실해야 하고, 3키 이하(`ls`, `cd`, `git`)는 바꾸지 않습니다. 한글 상태로 친 영어(`git push`)는 평소대로 돌아옵니다. 기호만 친 토큰(`echo 안녕 > out.txt`의 `>`, `|`, `>>`, `&&`)은 어느 상태에서 쳐도 친 글자 그대로입니다(평소에는 한글 상태에서 `>`가 자판표 글자 `.`). 어느 앱이든 메뉴에서 켜고 끌 수 있습니다.
- **저장**: `~/Library/Application Support/autohan0/settings.json`(켜기, 자판, 끈 앱, 엄격한 앱, Shift+Space), `learned.json`(배운 말).
- **진단 기록**: `"dev.autohan0.status"` 분산 알림을 보내면 `status.json`에 상태와 최근 키 처리 기록(`keys`, 400개)을 적습니다. 키 기록에는 키의 **종류**(글자 L·숫자 D·기호 P·⌫·␣·⏎)와 처리 결과(통과, 또는 몇 글자 지우고 몇 글자 넣음), 커서를 잊은 이유(클릭·포커스·앱 전환)만 남고 어떤 글자를 쳤는지는 남지 않습니다.
- **키 뗌**: 키 누름을 가로채 편집으로 바꿨으면 그 키의 뗌도 앱에 보내지 않습니다. 단, 꾹 누른 키(⌫ 반복)처럼 같은 누름의 키 누름이 한 번이라도 앱에 갔으면 뗌도 보냅니다. 삼키면 앱이 그 키가 계속 눌려 있다고 여겨 다음 누름 하나를 버립니다(Claude 앱에서 다 지우고 바로 다시 칠 때 첫 글자가 남던 원인).

### 엔진 연결과 키당 지연

1안(엔진·데이터를 JS 번들 하나로 묶어 JavaScriptCore에서 실행)으로 만들었습니다. Swift 쪽 진입점은 `EngineBridge.swift`이고, 키마다 `keyDown(keyCode, mods, now)` 한 번을 JSC C API로 부르고 결과를 문자열 하나(`<consume><thenOriginal><learned><mode><deleteCount>:<insert>`)로 받습니다.

| 측정 (Apple M3 Pro, `autohan0 --selftest`) | 결과 |
|---|---|
| 엔진 불러오기(모델 만들기 포함) | 약 0.2초 (앱은 뜰 때 백그라운드에서 하고 워밍업까지 함) |
| 키 1만 개 연속(Swift → JSC → Swift, 결과 해석 포함) | 평균 11µs, p99 약 30µs, 최대 약 0.5ms |
| 사람 치는 속도(60ms 간격 250키) | 평균 약 0.2ms, p99 약 0.45–0.5ms, 최대 약 0.6ms |
| 실제 앱 안 이벤트 탭 전체(메모·터미널 점검 중) | 평균 약 0.25ms(엔진 0.23ms), 최대 1.3ms |

평균이 기준(0.5ms)보다 한참 낮아서 2안(Swift 포팅)은 하지 않았습니다. 연속 입력(11µs)과 사람 속도(0.2ms)의 차이는 키 사이에 CPU 클럭과 캐시가 식어서 생기는 것으로, 앱 낮잠(App Nap)을 끄고 재도 같았습니다. 화면에 글자가 뜨기까지 걸리는 시간(수십 ms)에 비하면 체감되지 않는 크기입니다.

- **JIT 권한이 꼭 필요합니다.** `com.apple.security.cs.allow-jit` entitlement 없이 서명하면 JSC가 JIT을 끄고 인터프리터로만 돌아서 키당 평균 110µs(연속 입력), 엔진 불러오기 0.86초가 됩니다. `build.sh`가 `Resources/autohan0.entitlements`로 넣습니다.

### 점검

수용 테스트를 앱이 실제로 쓰는 경로(macOS 키 코드 → JSC → 편집 연산 → 가상 입력칸)로 돌리고 키당 지연을 잽니다. 권한이 필요 없습니다.

```bash
apps/macos/build/autohan0.app/Contents/MacOS/autohan0 --selftest
```

SPEC 7절 필수 23개(세부 케이스로 나눠 27개) + 권장 5개 + 백스페이스 3개, 35개 모두 통과합니다.

실제 앱 점검(본 앱이 켜져 있고 권한이 있을 때): 같은 서명의 두 번째 프로세스가 앞에 있는 앱의 입력칸에 고정된 키열을 키보드처럼 넣고, 한/영 키를 Caps Lock·🌐 방식(입력 소스 전환)과 입력 소스 단축키(F19 등) 두 가지로 누른 뒤, 결과를 손쉬운 사용 API로 읽어 `~/Library/Application Support/autohan0/inject-report.txt`에 적습니다. 엔터는 누르지 않습니다(터미널에서도 아무것도 실행되지 않음). 메모처럼 줄을 새로 시작해도 되는 앱에서는 `--fresh-line`을 붙입니다.

```bash
open -g -n apps/macos/build/autohan0.app --args --inject --fresh-line
```

**확인 결과 (2026-10-19, 세벌식 390 설정, ABC 입력 소스, gksdud 종료 상태):** 위 점검을 최종 빌드로 메모 3회, 터미널 1회 돌려 13단계가 모두 통과했습니다(배운 말 때문에 결과가 달라진 2회는 아래 참고해 제외).

|---|---|---|
| A 상태 `jfshea` → 치는 도중 `안녕`, 끝까지 `jfsheamfncj4` → `안녕하세요` | 통과 | 통과 |
| 가 상태 `git push origin main` → 영어 그대로, 모드 A | 통과 | 통과 |
| 치는 중 한/영 키 한 번(입력 소스 전환 = Caps Lock·🌐 방식) → `jfshea` | 통과 | 통과 |
| 치는 중 한/영 키 한 번(입력 소스 단축키 F19) → `o/jfs` | 통과 | 통과 |
| 띄운 뒤 한/영 키 빠르게 두 번(F19) → `yda0g␣` | 통과 | 통과 |
| 백스페이스 한 번 → 음절 하나(`안녕` → `안`), 이어 치기 → `안녕하세요` | 통과 | 통과 |

사용자가 실제 Caps Lock(이 Mac에서는 F19로 바뀌어 있음)으로 한/영 전환한 것도 상태 기록에서 확인했습니다. 점검을 거듭하다 같은 말을 두 번 되돌리면 그 말을 배워서(SPEC 21번 동작) 다음 점검부터 바뀌지 않으니, 여러 번 돌릴 때는 메뉴 › 배운 말에서 지우세요.


### 한계 (macOS 앱)

- **앱의 글자를 읽지 않고 엔진이 기억하는 대로 지웁니다.** 그래서 앱이 친 글을 스스로 바꾸면 어긋날 수 있습니다: 메모의 자동 대문자(`echo` → `Echo`)와 자동 고침(되돌린 `jfshea` → `joshes`), 인라인 예측 문구가 떠 있을 때의 백스페이스 등. 점검 중 메모에서 한 번(8회 중 1회), 바꿔 넣는 백스페이스가 앞 글자를 지우지 못해 `echo j안녕`이 된 적이 있습니다. 같은 줄에 이어 치는 조건으로 7번 더 돌렸을 때는 재현되지 않았고 터미널에서는 한 번도 없었습니다. 원인은 확인하지 못했습니다(메모의 인라인 예측·자동 고침이 그 순간의 백스페이스를 가져간 것으로 짐작). 이런 앱에서 거슬리면 시스템 설정 › 키보드 › 입력 소스의 "자동으로 맞춤법 수정"·"인라인 예측 텍스트 표시"를 끄거나 그 앱에서 autohan0을 끄세요. 클릭·방향키 등 commit 신호가 오면 다시 맞습니다.
- 숫자 키패드와 ⌥ 조합 문자(ABC 자판의 `å` 등)는 엔진에 넘기지 않고 그대로 둡니다. QWERTY 자판(ABC/U.S.)을 전제합니다.
- 한/영 키로 쓰는 Caps Lock·🌐은 macOS가 입력 소스를 바꾼 것을 보고 아는 방식이라, 시스템 설정에서 그 키가 입력 소스를 바꾸도록 되어 있어야 합니다.
- 비밀번호 칸 감지는 보안 입력과 `AXSecureTextField`만 봅니다. 손쉬운 사용 정보를 내주지 않는 앱의 자체 비밀번호 칸은 놓칠 수 있습니다.
- 공증·배포, 자동 업데이트, 앱 아이콘은 없습니다(로컬 서명).

## 무엇을 하나 (catchtype 동작의 세벌식판)

- **키마다 양쪽으로 읽습니다.** 지금까지 친 키열을 영어(QWERTY)와 세벌식 한글 두 방식으로 읽어 보고 말이 되는 쪽을 고릅니다.
- **치는 도중에 바꿉니다.** 영어 상태에서 `jf`까지만 쳐도 `아`가 되고, 상태(가/A)도 같이 바뀌어 다음 키부터 그대로 이어집니다.
- **반대 방향도 같습니다.** 한글 상태에서 친 `git push origin main`은 영어로 돌아옵니다. 단어가 끝날 때(띄어쓰기·엔터) 한 번 더 판정합니다(한글 상태 `he`: 치는 동안 녀 → 띄어쓰기에서 he).
- **섞인 단어는 나눕니다.** `AI로`, `deploy했는데`, `for문`, `README에`, `test도`처럼 영어 뒤 한글 조사·어미만 바꿉니다. 앞부분이 숫자·코드 토큰(`3개`, `10분`, `2025년에`, `v0.8.5로`, `k8s에`, `F1이`), 한 글자 라벨(`n제`, `x축`, `B급`, `A팀`), 약어(`UI같은건`, `API를`)여도, 닫는 따옴표·괄호 뒤(`"contents"라고`)여도 나눕니다. 한 글자 라벨은 뒤가 조사·단위·아는 낱말일 때만입니다. 한글 상태에서 Shift로 친 숫자 뒤 한글도 단위·조사로 봅니다(세벌식 최종 `KHK:hes` → 2024년).
- **대문자 약어와 코드 토큰은 그대로 둡니다.** `TV`, `README`, `PR`, `v2`, `build.sh`, `Q4`, `h264`, `k8s`.
- **URL·경로·주소는 두 모드 모두 그대로 둡니다.** `https://…`, `www.`, `~/`, `./`, `../`, `localhost:`, `/usr/local/bin`. `.`이나 `/`(ㅗ 키) 하나만으로는 아닙니다(`안녕.`, `AI로`).
- **영어 상태로 친 기호는 친 글자 그대로입니다.** 세벌식 최종에서 `~`는 한글 상태에선 `※`지만, 영어 상태로 친 `뭐라고~`는 `~`로 둡니다. Shift+기호가 자모인 키(`!` = ㄲ받침)는 음절에 붙을 때만 자모입니다(`닦`은 되고 `안녕!`은 느낌표).
- **앞 단어까지 고칩니다.** 양쪽 다 말이 되는 단어(`pea`/평, `it`/머, `hr`/내)는 보류해 두었다가, 다음 단어에서 확신이 생기면 앞 단어까지 다시 판정합니다. 엔터나 클릭(`commit`) 뒤로는 건드리지 않습니다.
- **백스페이스는 보이는 글자 하나를 지웁니다.** 한글은 음절 단위(`안녕` → `안`, 낱자모·쌍자음·겹받침도 한 글자), 영어는 글자 하나입니다. 지운 뒤 이어 치면 그 음절부터 다시 조합됩니다.
- **한/영 키로 되돌립니다.** 치는 도중 바뀐 단어는 한/영 키 한 번, 띄어쓰기 뒤 고쳐진 앞 단어는 400ms 안에 두 번 누르면 친 그대로 돌아갑니다. 한 번만 누르면 평소의 한/영 전환입니다.
- **같은 말을 두 번 되돌리면 배웁니다.** 다음부터 그 키열은 바꾸지 않습니다. 한 번 되돌린 말은 친 그대로 쪽으로 조금(+3) 기울여 두어, 애매한 말(`nd`/시)은 그대로 두고 확실한 말(`jfshea`)은 여전히 바꿉니다. 둘 다 "배운 말" 목록에서 보고 지울 수 있습니다(데모 목록은 이 브라우저의 localStorage에만 저장).
- **판단은 전부 로컬입니다.** 엔진에 든 단어 목록과 통계로만 판단하고, 키 하나 판단 시간은 평균 약 10µs입니다.

## 세벌식에서 달라지는 점

세벌식은 두벌식과 달리 초성·중성·종성이 서로 다른 키라서, 엔진 설계가 이렇게 달라집니다.

1. **음절 경계가 결정적입니다.** 오른손(`h j k l ; ' y u i o p n m 0`)이 초성, 왼손 가운데·아래와 `4–9`가 중성, 왼손 위·아래와 `1 2 3`이 종성입니다. 두벌식의 도깨비불 모호성이 없어서, 키열을 바로 `초 중 [종]` 음절로 조합할 수 있습니다.
2. **구조 검사 자체가 강한 신호입니다.** 한글로 읽히려면 `초성 중성 [종성]`이 반복되어야 해서, 한글 상태에서 친 영어 단어는 대부분 첫 한두 키에서 걸러집니다(`git` → ㅡ…, `push` → ㅍㄷㄴㄴ, `hello` → 녀ㅉㅊ). 그래서 영어 쪽 오변환이 두벌식보다 적습니다.
3. **그래도 양쪽 다 되는 짧은 단어가 있습니다.** `it`→머, `if`→마, `of`→차, `me`→혀, `id`→미, `yes`→련, `pea`→평, `hr`→내 등. 이런 단어는 단어 빈도, 지금 모드, 앞뒤 단어의 언어로 정하고, 애매하면 보류합니다.
4. **입력은 반드시 "물리 키 + Shift"로 받습니다.** 세벌식 최종은 Shift 조합이 QWERTY와 다른 기호·숫자를 냅니다(Shift+J→`1`, Shift+B→`?`, `[`→`(` …). 엔진은 QWERTY ASCII 키를 받고, 영어 후보는 그 문자 그대로, 한글 후보는 자판표로 읽습니다. 웹 데모는 `event.code`+`shiftKey`로 이 문자를 구합니다(`packages/engine/src/keymap.ts`).
5. **숫자열이 자모입니다(세벌식 최종).** `1`→ㅎ받침, `2`→ㅆ받침, `3`→ㅂ받침, `4`→ㅛ, … `0`→ㅋ초성. 한글 상태의 숫자는 Shift로 칩니다(`KHK:` = 2024). 그래서 한글 상태에서는 "모두 대문자면 영어로 둔다" 규칙을 쓰지 않고(숫자를 친 것이므로), 영어 상태에서만 씁니다.
6. **같은 자모에 키가 둘인 경우**(ㅗ: `v`와 `/`, ㅜ: `b`와 `9`)를 둘 다 받습니다.
7. **쌍초성은 같은 키 두 번**(ㄲ = `kk`), **겹받침은 전용 키 또는 받침 두 키**(ㄺ = `@` 또는 `wx`), **겹모음은 중성 두 키**(ㅘ = `/f`)입니다. 조합 규칙은 libhangul `hangul-combination-default.xml`을 그대로 씁니다.
8. catchtype의 "쌍자음 치고 Shift 늦게 떼기" 관용은 세벌식에선 Shift가 다른 자모·기호라서 적용하지 않습니다.
9. 한글 상태에서 친 기호·숫자는 자판표가 내는 문자(`·`, `“`, `※`, 숫자 …)를 한글 후보에 넣습니다.

자판 데이터는 libhangul XML에서 생성하므로(`scripts/build_layouts.mjs`), 다른 세벌식 자판도 XML만 더하면 됩니다. 세벌식 390은 기호만 QWERTY에 가깝고 소문자·숫자 자모는 최종과 같습니다.

### 엔진 API (2단계 래퍼용)

```ts
import { Engine } from '@autohan0/engine';

const engine = new Engine({ layout: '3f', mode: 'en', learned: savedLearnedWords });
const r = engine.process({ type: 'key', ch: 'j' });   // QWERTY ASCII 한 글자(물리 키 + Shift)
// 그 밖의 이벤트: space, enter, backspace, toggle(한/영 키), commit(클릭·커서 이동), reset
// toggle은 두 번 누르기 판정 때문에 시각을 넘긴다: engine.process({ type: 'toggle' }, performance.now())

r.text            // 전체 텍스트
r.mode            // 'ko' | 'en'  (가 / A)
r.edit            // { deleteCount, insert }: 커서 앞에서 코드포인트 deleteCount개 지우고 insert를 넣으면 됨
r.words           // 단어별 표시 정보: held(보류), changed(자동으로 바뀜), locked(고정) …
r.committedLength // 더 바뀌지 않는 앞부분 길이

engine.setLayout('39');        // 자판 교체(그때까지 친 글은 확정)
engine.setBypass(true);        // 비밀번호 칸 등: 고치지 않음
engine.learnedWords();         // 배운 말 목록
engine.forgetLearned('jfshea');
engine.explain('it', 'ko');    // 디버그: 후보별 점수
```

OS 수준 래퍼는 키를 가로채 `process()`에 넘기고, 돌려받은 `edit`대로 백스페이스 n번 + 문자열 입력을 하면 됩니다.

## 판단 방식

한 단어(띄어쓰기 사이)의 키열을 세 가지로 읽고, 같은 키열이 각 언어에서 나올 **로그 확률**로 비교합니다. 그래서 두 점수를 바로 견줄 수 있습니다.

- **영어**: 단어 빈도(wordfreq) + 문자 5-gram(Witten-Bell)의 혼합. 치는 도중에는 "이 접두로 시작하는 단어들의 빈도 합"을 씁니다. 대·소문자 모양(`README`, `Figma`, `iPhone`), 숫자·기호가 붙은 코드 토큰(`v2`, `build.sh`, `0xff`)도 점수에 들어갑니다. 2–6자 대문자 약어(`UI`, `PR`, `API`)는 소문자 단어 `ui`의 빈도가 아니라 길이별 고정 점수(2자 log 0.001, 한 자마다 ×0.25)로, 숫자에 붙은 한 글자(`k8s`, `h264`, `3e-4`; 대문자이거나 영숫자 3자 이상일 때만 — `j4`는 요, `m5`는 휴)는 단어 `k`가 아니라 코드 토큰 글자(log 0.15)로, 숫자 뒤 서수·단위(`2nd`, `3kg`, `24hrs`; `12nd`는 서수가 아니라 12시)는 log 0.3으로 잽니다.
- **한글**: 세벌식 조합 → 구조 검사(음절이 못 되는 자모가 있으면 탈락) → 어절 빈도(FrequencyWords) + 자모 5-gram 혼합. 드문 자모 이음(주→ㅋ)에서 확률이 무너지지 않도록 "초·중·종 구조" 바닥 모형을 10% 섞습니다. 영어 상태로 친 단어에서 단어 목록에 한 번도 나오지 않는 음절(`긘`, `뗘`)은 음절마다 log 0.01을 더 뺍니다(한글 상태로 일부러 친 `캬`, `챠트`는 그대로). 영어 상태로 친 단어에서 Shift+글자를 숫자·기호로 읽는 키(`K` → 2, `N` → -)는 키마다 log 0.001을 뺍니다(한글 상태로 친 `KHK:` = 2024는 그대로).
- **영어 + 한글 꼬리**: 앞부분이 영어 단어/약어/숫자·코드 토큰이거나 한 글자 라벨(뒤가 조사·단위·아는 낱말일 때만, 라벨 점수 log 0.01)이고, 그 앞부분을 한글로 읽은 것보다 영어가 더 그럴듯하며, 뒷부분이 조사·어미·단위·라벨 명사(제, 축, 급, 팀 …)로 읽힐 때(`AI로`, `deploy했는데`, `for문`, `3개`, `n제`). 나누는 자리는 영숫자 뒤나 닫는 따옴표·괄호 뒤입니다.
- **URL·경로**(`://`, `www.`, `~/`, `./`, `/x/`, 자판에서 `@`가 기호일 때 `x@y`)는 영어 후보만 둡니다.

여기에 사전 확률을 더합니다: 단어를 시작할 때의 모드(+2.5), 앞 단어와 같은 언어(+2; 숫자만 친 앞 단어는 친 모드의 언어로 칩니다 — `1 hr`는 영어), 한 번 되돌린 키열은 친 그대로 쪽(+3). 엄격 모드에서는 영어 상태로 친 단어의 한글·분리 읽기에서 4를 빼고 3키 이하는 후보에서 빼며, 기호만으로 된 토큰(`>`, `|`, `&&`)은 모드와 상관없이 영어 후보만 둡니다. 치는 도중에는 지금 보이는 쪽에 +3을 주어 깜빡임을 막고, 단어가 끝나면 다시 판정합니다. 이긴 쪽과 4 이내로 비슷하면 지금 보이는 쪽을 유지하고 **보류**로 표시합니다. 다음 단어가 증거만으로(사전 확률 없이) 6 이상 확실해지면, 보류된 앞 단어를 그 언어 쪽 +3.4로 다시 판정합니다(숫자만 친 상태에서는 기다립니다: `2024년` 뒤의 `4`는 `4분기`가 될 수 있으므로). 엔터에서는 더 올 문맥이 없으므로 보류를 풀되, 보이던 쪽과 차이가 3 미만이면 그대로 둡니다(잘못 바꾸는 것이 안 바꾸는 것보다 나쁘므로). 값은 `EngineParams`로 바꿀 수 있습니다.

## 알려진 한계

- **한 음절 한글 뒤 영어**(`챗GPT`)처럼 한글 → 영어로 바뀌는 단어 안 경계는 나누지 않습니다(catchtype과 같음).
- **짧고 애매한 단어는 빈도와 문맥으로만 정합니다.** 권장 26번(`if`/마)은 통과하지만 차이가 로그 확률로 약 0.1밖에 안 됩니다. `마`가 자막 말뭉치에서 꽤 흔하기 때문입니다(`하지 마`). `id`/미도 비슷하게 아슬아슬합니다. 데이터나 매개변수를 바꾸면 뒤집힐 수 있어서, 26번은 수용 테스트로, `id is required`(가 상태)는 개발자 대화 평가 문장으로 넣어 두어 바뀌면 바로 드러나게 했습니다. `걍`처럼 문맥이 더 필요한 말, `뭄바이`처럼 드문 음절로 시작하는 말도 catchtype처럼 놓칠 수 있습니다.
- **영어 상태에서 Shift로 친 숫자만으로 된 토큰**(세벌식 최종에서 `75` = `IY`)은 "모두 대문자 약어" 규칙 때문에 영어로 남습니다. 이 규칙을 숫자 쪽으로 풀면 `OK`(= `82`), `HI`(= `07`) 같은 약어가 숫자로 바뀌어서 일부러 남겼습니다. 숫자 뒤에 한글이 붙으면(`KHK:hes` → 2024년) 정상으로 바뀝니다.
- **문맥은 앞뒤 한 단어의 언어만 봅니다.** 단어 bigram 같은 더 긴 문맥은 없습니다. 보류는 바로 뒤 단어에서 풀리고, 엔터에서는 차이가 3 이상일 때만 바뀌며, 클릭(`commit`) 뒤에는 보이던 대로 확정됩니다. 그래서 한 줄에 애매한 단어 하나만 치면(가 상태 `of`⏎) 지금 모드 쪽(차)으로 남습니다.
- **한국어 빈도가 자막(구어)에서 왔습니다.** 기술 용어(`로드맵`, `공유드려요`)는 사전에 없고 자모 n-gram으로 판단합니다. 지금 평가에서는 문제가 없었지만, 아주 드문 고유명사 음역은 영어로 남을 수 있습니다.
- **데모 편집기는 끝에만 칩니다.** 클릭·방향키는 "커서 이동"(`commit`)으로 보고 그 앞을 확정할 뿐, 실제로 커서를 옮기지는 않습니다. 숫자 키패드와 물리 키보드가 없는 모바일은 지원하지 않습니다. `event.code`가 없는 가상 키보드는 `event.key`가 ASCII일 때만 받습니다.
- **배운 말**은 "같은 모드 + 같은 키열"로 기억합니다. 배운 말의 앞부분을 치는 동안에는 치는 도중 전환을 미루고, 키열이 달라지면 평소대로 판단합니다. 한 번 되돌린 말의 기울기(+3)로는 `hr`/내처럼 차이가 3을 넘는 말은 안 뒤집히므로 한 번 더 되돌려야 합니다. 30일 뒤 잊는 것 같은 만료는 없습니다.
- **한 글자 영어 + 한글**(`n제`, `x축`)은 뒤가 조사·단위·아는 낱말일 때만 나눕니다. 목록에 없는 낱말(`n번째`는 되지만 드문 명사)은 안 나뉠 수 있습니다.
- **한글 상태로 바뀐 뒤 친 기호는 자판표 글자입니다.** 세벌식 최종에서 `오늘 날씨 좋다~`처럼 첫 단어에서 한글로 바뀐 뒤 친 `~`는 `※`가 됩니다(한글 입력기와 같음). 영어 상태로 친 단어 안의 기호만 그대로 둡니다. 엄격 모드(터미널)에서는 기호만으로 된 단독 토큰(`echo 안녕 > out.txt`의 `>`, `|`, `>>`, `&&`)을 모드와 상관없이 친 글자 그대로 두지만, 단어에 붙은 기호(`좋다~`)는 거기서도 자판표 글자입니다.
- **`@`가 자모인 자판**(최종: ㄺ받침)에서는 이메일(`x@y`) 보호 규칙을 쓰지 않습니다. 390에서는 씁니다.
- **영어 상태로 친 `2시`(키 `2nd`)는 서수 `2nd`로 남습니다**(22시, 32시도). 뒤에 조사가 붙으면(`2시에`) 한글로 바뀝니다. `k8s에`는 영어 상태로 쳤을 때만 나뉩니다(한글 상태의 `긘에`는 친 그대로).
- 두벌식, 모아치기, 한자 변환, Windows·Linux 키 가로채기는 범위 밖입니다. macOS 앱의 한계는 [그 절](#한계-macos-앱)에 따로 적었습니다.
